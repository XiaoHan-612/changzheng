## 一、旧实现薄在哪（这是重做的理由，不是口味问题）

`runSentry(knownPassword, container, opts)` —— 五个写死的信号，每个三个选项，
选对加一分，最后 `hits / 5` 就是分数。三处硬伤，任何一处都足以毁掉这个玩法：

| # | 问题 | 后果 |
|---|---|---|
| 1 | **五个信号里，除口令题外正确答案全部落在 index 1（中间那个）** | 玩家点三次就发现"永远点中间"，剩下两下是盲点。玩法退化成装饰。 |
| 2 | **没有代价** | 处置错了只是少一分。`wrong` 音效一响，下一个信号照旧，什么都不变。 |
| 3 | **没有失败** | 最低 0 分，不存在"输"。而这支玩法的史实内核恰恰是"误报、漏报都可能让整支队伍付出代价"。 |
| 4 | 画面是白纸 + 一行 20px 字 + 一排箭头 | `.sentry-box` 就是一张纸。所谓"听声辨位"完全没有被表达：玩家看到的是**文字**，不是**声音**。 |
| 5 | `dir-arrows` 写的是 `idx % 2 === 0 ? '← · →' : '· ↑ ·'` | 跟信号内容毫无关系，纯装饰。 |

史实锚点（`data/facts.json · h_sentry`）：

> 行军宿营时部队设岗哨、定口令，以防敌特袭扰与野兽；**误报、漏报都可能让整支队伍付出代价**，
> 因此哨位强调**听声辨向、口令对答与不轻易暴露位置**。

新版的三个机制就是从这句里拆出来的：**方位盘**（听声辨向）、**口令题**（口令对答）、
**马灯**（不轻易暴露位置）。

## 三、这一版是什么

### 两个资源（不是一个）—— 这是和旧版最大的差别

| 资源 | 含义 | 怎么涨 |
|---|---|---|
| **惊动** | 误报：把动静做大了 | 拉栓 / 开枪 / 喊人 / 挪哨位 / 举灯 |
| **漏** | 漏报：把该管的放过去了 | 不管它 / 蹲回去接着听 / 打盹 |

**两个方向都要付代价，而且上限不同**：`惊动 ≥ 4` 哨位被摸熟（`exposed`），
`漏 ≥ 3` 有人摸到营地边上（`breached`）。**漏的上限更低 —— 漏比误报更致命，
所以"一路保守"这条懒路走得比"一路激进"更短。**

### 马灯（全场一盏）

- 用灯 = 当场看清这个信号的真值（把"你猜"变成"你知道"）；
- 代价 = **惊动 +1**，而且**用掉就没了**；
- 花在"你本来读得出来"的信号上，界面会当场告诉你「这一句其实你读得出来 —— 灯白举了」。

灯的代价看着只有 1 点，**但真正的稀缺不是预算，是确定性**：五个信号里
**有两个是读不出来的**（界面明写"你拿不准"），而灯只够照一个。
剩下那一个只能赌 —— 这是这个玩法真正的决策。

### 五个信号

| # | 信号 | 方位 | 距离 | 读得出来吗 | 真值 |
|---|---|---|---|---|---|
| 1 | 脚步 | 左前 | 近 | **能**（"两点一顿"= 两条腿） | 有情况 |
| 2 | 光点 | 右前 | 远 | **不能**（知道是烟头，不知道是谁的） | 每局随机 |
| 3 | 口令 | 正前 | 近 | 能（学过口令就是道奖励题） | 有情况 |
| 4 | 野物 | 右前 | 远 | **能**（"吼完就走"= 它会躲你） | 没情况 |
| 5 | 静默 | 身后 | 近 | **不能**（"什么都没有"可能是真没有，也可能有人也在等） | 每局随机 |

**两条"拿不准"的信号没有支配解**：真值是有情况时，"按最坏的打算"是对的；
真值是没情况时，"接着听别的"才是对的 —— **同一个选项在两个真值下档位不同**，
所以不存在"永远选那个最谨慎的"。这一点有断言守着（`qa-sentry.mjs` A2 段）。

### 口令题（同一个点，两种题面）

- **学过口令**（夜校那支的产出）→ 题面把口令喂进来，正确处置是"压低嗓子报回去"。
  这是**做夜校的回报**：白送一个得当。
- **没学过** → 题面是"你脑子里一空"，正确处置是"压低身子不答，等他先动"
  （史实：不轻易暴露位置）。

产出口径不变：`detail.passwordUsed` 那条线仍然成立，下游不用改。

### 失败线两条（都在**结算屏**才落地）

局内只给计数，不给结论 —— 漏的代价在当晚是**看不见**的。

```
exposed   惊动 ≥ 4   分 ≤ 0.25   "那盏灯你举得太久了。天亮前，东边的草动了一下，又不动了。"
breached  漏   ≥ 3   分 ≤ 0.30   "草里一行脚印，方向和你们走的不一样。他没有声张。"
```

## 四、接不接 AI：**不接。这是量过之后的决定，不是省事**

用户定的口径（2026-09-15）：**AI 必须融进游戏，但前提是不许影响体验；超过 10 秒就换固定内容。**

在**同一个比赛网关**上实测（2026-09-15 本轮复测）：

| 调用 | 结果 |
|---|---|
| `npm run check:glm` 极简探测（26 → 上限 256 tokens） | **6793 ms**，`finish=length` —— 256 个 token **全烧在隐藏推理上**，连 `{"ok":true` 都没写完 |
| `glm-5.3-flash`（唯一可能更快的档） | **HTTP 403，本 Key 无权限** |
| 叙事类调用（分糖那轮） | 输出 **28 个字** 也要 **19–39 秒**；判词 **53–64 秒** |

→ 最省的一条也要 6.8 秒且内容不完整。而这个玩法**没有任何一秒可以让玩家站着等** ——
每按一次处置就要看下一个信号。所以游戏内 **0 次模型调用**。
这一条有硬证据：`qa-sentry.mjs` C 段装了一个 `/api/decide` 计数器，
**整局跑完计数为 0**。

**AI 并没有缺席。** 夜岗在主线上本来就有一次结算调用：
`server/ai.js:273` 的 `callType === 'minigame_review'` + `operation.type === 'sentry'` 分支，
prompt 早就写好了，而且那句

> "按误报与漏报写后果：漏报要付代价，误报同样要付代价，别只奖励保守。"

**正好就是这一版的机制。** 接线后由它接管，**不需要新增 callType，也不需要改 schema**
（所以 `schema.test.js` 那 19 类不用动）。

新玩法给的 `detail.effects` 是**空对象** —— 固定判词不编数值，数值由主线那一次调用给。
这是故意的：机制是作者写的，话和数值是模型说的。

## 七、这一轮踩到的坑（都是新的，后人别再踩）

1. **【断言自己错】"恰好一个正确项"必须逐真值量。**
   两条 `open` 信号在 `threat` / `harmless` 下**各有自己的正确项，而且故意不是同一个**
   （这就是"没有支配解"）。第一版断言写成"`tier` 里出现过 `right` 就算一个"，
   于是这两条各被算成 2 个 → **报了两条假红**。老规矩：红灯先怀疑断言自己。
   现在这条度量自己也有反证（把一个正确项改成 `over` → 计数 1→0；全改成正确项 → 3）。

2. **【契约】`settle()` 里必须摘掉灯键的 `[data-mini-action]`。**
   契约是"不可操作的元素不要带这个标记"。收场后灯键只是 `disabled`，
   于是"结束后交互元素归零"当场红（剩 1 个）。现在 `lampBtn.removeAttribute('data-mini-action')`。

3. **【画面】结算时 `paintDial()` 会把方位盘擦空。**
   `settle()` 里 `idx = plan.length`，而 `paintDial()` 读 `plan[idx]` → 越界 → `innerHTML=''`
   → 结算屏上剩一个 **176px 的空框**（"天要亮了"配个空框，看着像坏了）。
   改成**冻在最后一个信号上**。顺带：`locator.screenshot()` 在这个位置会等
   "元素稳定" **30 秒超时**（原因不明，可能是那个空框）——
   **别跟它较劲**，方位盘本来是自己光栅出来的，直接 `canvas.toDataURL()` 写 PNG 更清楚也更快。

4. **【SVG】独立成图必须有 `xmlns`。**
   `data:image/svg+xml` + `new Image()` 这条路，SVG 根节点没有 `xmlns` 就解析失败。
   页面内联的 SVG 由 HTML 解析器自动补命名空间，所以**只有"序列化成图"这一条路会踩**。

5. **【像素断言】色彩窗口必须带 alpha 硬条件。**
   涟漪是 `rgba(196,220,246,.60)`，而**未激活扇区的填充是 `rgba(232,214,190,.045)`、
   激活扇区是 `rgba(143,182,214,.20)`** —— 只按色相筛，整块扇形都会被算成"涟漪像素"，
   断言当场失去检出能力。加 `alpha ≥ 0.5` 才把填充排掉（实测：涟漪 1327 个 / 填充 0 个）。

6. `minigame-lab.html` 的 `select()` 在 `load` 之后才跑，它会 `board-body.innerHTML = ''`。
   想往里注入自己的容器，**必须 `waitForFunction(() => !!document.getElementById('mini-host'))` 等它装完**，
   否则注入的容器会被当场删掉（表现是"按钮解析到了却被 detach"）。
   另外调试台一打开就自动跑列表第一个玩法（那支会真调模型），
   所以每个页面都要先 `addInitScript` 把 `/api/decide` 挡掉。

7. **【像素断言】色彩窗口要按"具体元素"开，不能按"看起来是金色"开。**
   照亮态最初用 `r−b > 60 && r > 150` 筛金色 —— 结果把**盘中央的类型字 `#f2d79a`**
   （r−b = 88）也数了进来，它有一半笔画落在扇区外：
   四条断言全红，假阳性 **265–808 个 / 个**。金涟漪 `#e8c073` 的 r−b = 117，
   所以窗口收到 `r−b > 105` 才把两者分开。
   **同一个色族在不同状态下往往是不同的元素** —— 窗口要窄到只认目标，而不是认色相。

8. **排掉圆心区要按真实几何算，不要凭感觉。** 类型字最远的角在 r ≈ 18（viewBox 单位），
   涟漪最内一道在 r = 34 —— 取 `22` 两边都安全。第一版写 `8`，等于没排。

9. **【画面】上一题的反馈留在屏幕上，必须标出处。**
   反馈行贴在选项下面，进下一个信号时如果不标，看起来就像在说当前这个信号 ——
   截图里「处置得当。你压住了动静，也没放它过去。」正好压在"光点"那条题下面，一眼误读。
   改成 `上一个（脚步）：…` 就成了一行流水，既不留歧义也不丢信息。
   （顺带：这条断言的"反证"就是修改前那张截图 —— 那时这行文本就是 `处置得当。…`，
   正则 `^上一个（` 匹配不上，必红。）

10. **【画面】盘外一圈没有余量，别往里塞字。** 方位盘原来还有一行「已照亮」放在 `cy + 76`
    （y = 164），正好压在底部「身后」标签（y ≈ 156.5）上。
   而"被照亮"本来就有三重编码（扇区填充转暖、涟漪与源点转金、面板里那行「照见了：…」）——
   再塞一行字是装饰，不是信息。**删掉比挪位置好。**

11. **试色：夜底上 `.20` 的填充冷暖两态只差一个色相，实测很容易看混** → 提到 `.40`。
   但**必须 < 0.5** —— 视觉断言拿 `alpha ≥ 0.5` 当硬条件把"扇区填充"排除在"涟漪像素"之外，
   一超过就会把整块扇形算成涟漪，断言当场失效。
   **改动颜色时先去确认有没有断言绑在它的 alpha 或色相上。**

## 八、设计上已知的取舍（别当成 bug）

- **5/5（`clean`）需要赌对那一下。** 五个信号里两条读不出来、灯只够照一条，
  所以剩下那条是 50/50。**稳定成绩是 0.8**，1.0 是运气和判断都到位。
  这是故意的：史实里哨兵本来就"不可能都知道"。
- **灯的代价只有 1 点惊动，所以它不是"用不起"，而是"只够用一次"。**
  真正的稀缺是确定性，不是预算。对本来就判得全对的玩家，灯的得失不明显 ——
  但它对**会犯一两个错**的玩家是有意义的（灯 + 2 次误报 = 3，安全；灯 + 3 次 = 4，暴露）。
- **`漏` 在局内是看得见计数的**（为了机制可学），但它的**后果**要到结算屏才落地。
  这一点和分糖不一样：分糖是连计数都不给，让玩家事后才知道给错了。
- **野物那条没有 `under` 选项** —— 一只走掉的野鸭，你没法"漏掉"它。
  所以它只能提供 `over`，不提供 `miss`。这是内容上的不对称，不是漏写。
