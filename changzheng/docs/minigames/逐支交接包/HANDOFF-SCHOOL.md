# 《夜校识字》两条路 · 交接包（act2 遵义 / act4 草地 · 夜校这个点）

> 交接说明：这份文档是"拎起就能接着干"用的。**一灯油**（分光）与**知识竞答**（AI 当场出题）
> 是同一个点上的两条路，由**入口屏**让玩家自己挑。三条都**没有接入主线**。
> 验收命令、对照数字、踩过的坑都在下面，尤其§九 —— 有两条 P0 是肉眼看不出来的。

## 二、它替掉的那个是什么样

`public/js/minigames.js:307` 的 `runNightSchool`，58 行：

- 三道**写死**的单选题，而且 **三道的正确答案都是 A**（源码里就是 `a: 0`）——
  一路点 A 就是 3/3 满分；
- "今晚口令"写死成 `'瑞金'`；
- 全屏**没有一个 `data-*` 标记**，自动化只能干等（交接文档里记过这笔债）；
- **模型 0 次调用**：模型只在最后被叫来写一段旁白。

用户对这个点的原话：

> "现在不就是直接出题加回答吗……我想的方法是就让模型参与到这个游戏中，而且让这个游戏更好玩一点，
> 因为现在只是知识竞答，就是答题，你没有什么可玩性对吧？"

后来又补了一句关键要求：

> "把原来的版本保留上，但是原来版本那个题要由 AI 随机出……在这一幕这一个点上，你可以选择。"

所以这一版**不是替换旧的竞答，而是把它修好、和新的并排放**，让玩家自己选。

## 三、这一版是什么

### 3.1 《一灯油》——考"怎么分光"

一盏马灯、一片光圈、**22 秒油**。木牌上竖着三格，从上到下是**口令 / 地名 / 人名**
（位置固定，玩家才记得住该往哪儿照）。

- 光圈跟着指针走；**总教学吞吐恒为 1 秒/秒**，按距离劈给三个字。
- `R_OUT = 0.85 × 格高 = 93.5`，而相邻两格中心相距 `110` —— **正对一个字时，隔壁那个一点光都分不到**。
  反过来把光停在交界上，两个字会各拿**一半速率**（合起来仍是 1 秒/秒，因为做了归一化）。
  实测这一条是"保守打法"而不是失误，见 §七 的 S5。
- 三个字的总学费 = `22 × 0.95 = 20.9` 秒，**油只比需要多 1.1 秒**：
  瞄准不差分毫才勉强教得完三个，手一抖就只够两个。
- 木牌上**不写**字是什么、解释是什么 —— **光落上去才看得见**（解释在舞台底部的"读字条"上念）。

**三种收场**（都会真的发生）：

| 收场 | 含义 |
|---|---|
| `taught` | 照透了，这个字真教出去了，会往下传 |
| `half` | 照了一半：只记了个大概，**传下去会走样**（模型要写出它歪成什么字） |
| `none` | 一点没照到：今晚没教 |

**最坏的不是"没教"，是"全教歪了"**：三个字都半懂（0.40）比"砍掉口令、另两个教全"（0.50）分更低。
这条是刻意调的 —— `HALF_CREDIT = 0.4` 就是为它降下来的（原本 0.5 时两者同分）。

### 3.2 《知识竞答》——考"限时里认不认得出来"

教员把今天走过的路出成**三道题写在沙地上**，每题四个选项，**一题一次机会、14 秒香头**。

- 题目**由模型当场出**（`school_quiz` 一次调用出三道 + 定今晚口令），每次都不一样。
- 超时 = 答错，**都算"记歪了"**：错的那一项今晚会被当成对的记住。
- 口令题答错 → `detail.password` 为空 → 下游《夜岗》走"对不上暗号"的分支。
- 契约要求的观测状态：`miniQ` / `miniLeft` / `miniScore` / `miniAnswer` / `miniPicked` / `miniOutcome`。

### 3.3 入口 —— 选择本身就是决策

入口屏把两条路摆在明面上，每条都写清**它考什么、代价是什么**，再让玩家点。
两个操作标记：`[data-mini-action="pick-lamp"]` / `[data-mini-action="pick-quiz"]`。
选中后 `container.dataset.miniPick` 记下 `lamp|quiz`，`dataset.mini` 被改写为所选玩法的 id，
**并顺手把板屏题名 `#board-title` 换成那条路的题名**（`boardTitle` 字段）。
换题名这条是必须的：入口叫"两条路（选择入口）"，玩家一挑就该变成"一灯油 / 知识竞答"，
否则接线后板头会一直挂着"选择入口"而人在答竞答 —— 一眼就假。
调试台和主线用的是同一个 id（`#board-title`），所以入口直接写就好，取不到就跳过。

### 3.4 两条路的产出**故意对齐**

```js
{ score, detail: {
    password,            // 教成/答对才给；否则空串
    passwordOk,          // 下游《夜岗》只看这一个
    passwordRemembered,
    outcome,             // all | two | one | none | wrong-all | pw-missing | partial | nothing + dir:'lamp'|'quiz'
}}
```

下游 `main.js:1632`（夜岗那条"未学过口令只能硬扛"的分支）**不需要知道玩家走了哪条路**。

## 六、机制数值（都是调过的，别随手改）

### 一灯油

| 常量 | 值 | 为什么是这个值 |
|---|---|---|
| `OIL_SECONDS` | 22 | 一盏马灯烧一夜的"可玩化"时长 |
| `NEED_BUDGET` | `OIL × 0.95 = 20.9` | **只留 1.1 秒余量**：三个字刚好教不完，取舍被迫发生 |
| `R_IN` / `R_OUT` | `0.55 × 格高` / `0.85 × 格高` | `R_OUT (=93.5) < 相邻中心距 (=110)`：正对一个字时隔壁分不到光。**吞吐是归一化的**（`prog += dt·raw/Σraw`），所以"劈两半"= 各半速，总速率仍是 1/秒 |
| `LEVEL_MUL` | 生字 1.7 / 半熟字 0.55 | 学费按生熟分档，归一化到 `NEED_BUDGET` |
| 权重 | 口令 0.50 / 地名 0.30 / 人名 0.20 | 口令最贵 —— 夜岗要用 |
| `HALF_CREDIT` | 0.4 | **低于"另两个教全"(0.50)**：全教歪比不上砍掉一个 |
| `HALF_AT` | 0.42 | 进度超 42% 才算"照到一半"，否则等于没照 |
| 上限 | 0.98 | 和弯针那轮同一条约定：不给满分 |

## 七、对照实测（同一份代码，不同打法）

### 一灯油 · 六种打法（固定课本，0 次模型调用）

| 打法 | 分 | 结局 | 三个字 | 剩油 | 口令 |
|---|---|---|---|---|---|
| S1 精瞄，三个字都教 | **0.980** | `all` | taught/taught/taught | 0% | 可用 ✓ |
| S2 精瞄口令+地名，收灯 | **0.800** | `two` | taught/taught/none | 45% | 可用 ✓ |
| S3 只精瞄口令，收灯 | **0.500** | `partial` | taught/none/none | 86% | 可用 ✓ |
| S4 砍掉口令：地名+人名 | **0.500** | `two` | none/taught/taught | 18% | **空串 ✗** |
| S5 灯停在①与②的交界 | **0.800** | `two` | taught/taught/none | 0% | 可用 ✓ |
| S6 灯照夜空（一个字都不教） | **0.000** | `nothing` | none/none/none | 0% | 空串 ✗ |

**4 档 / 6 种打法。**

读法三条：

1. **S3 与 S4 同为 0.50，但结局词不同**（`partial` vs `two`）—— 这是刻意的：
   同样是半分，"只保住口令"和"丢掉口令"在夜岗那一关后果完全不同
   （S4 的 `detail.password` 是空串，夜岗直接走"对不上暗号"的分支）。
2. **S5 与 S2 同分不是 bug**：吞吐做了归一化（`prog += dt·raw/Σraw`），
   所以"劈成两半"合起来正好等于一次专攻的速度。停在交界于是是一种**保守打法**：
   两个字各半速、第三个别想、油全烧光。要拿 0.980 必须精确到 **1.1 秒以内**。
   （这一条是实测出来的，与设计初稿里"劈两半就谁都不够"的想当然不一样 —— 见 §九-9。）
3. **S6 = 0** 说明"什么都不做"真的有后果，不是走过场。

### 知识竞答 · 三档（固定题，0 次调用）

| 打法 | 分 | 结局 | 口令 |
|---|---|---|---|
| 全答对 | 0.980 | all | 可用（`passwordOk=true`） |
| 全答错 | 0.000 | none | 空串，但 `passwordRemembered=true`（听过、记歪了） |
| 全超时 | 0.000 | none | 空串，每题 `timeout=true`、`picked=-1` |

### 模型路径（真调用）

- 一灯油：模型从候选词池里取 `佑←班佑 / 盖←毛儿盖 / 号←小号手`（另一次跑出 `巴←巴西 / 佑←班佑 / 号←小号手`），
  逐字过闸（来源词在池里 ✓ / 这个字真出现在来源词里 ✓ / 单字 ✓）。
- 竞答：模型读到了调试台给的假流水，出了一道
  **"今天陷进沼泽，'陷'字旁边是两个'阝'还是……来，哪个是'陷'？"**，干扰项 `馅/谄/掐` —— 全是形近字。
- 三道题的正确项下标实测 `0,1,0` → **distinct = 2**（旧版三道全在 A；闸会在"三道同位置"时就地打散）。

## 八、模型参与在哪（三处，不是一处文案）

1. **`school_lesson`**（一灯油）：**定今晚的课本** —— 三个字、三个解释、今晚口令。
   客户端 `gateLesson()` 是纯字符串闸：`from` 必须在候选词池里、`ch` 必须真出现在 `from` 里、
   三种 kind 各一。**模型的字一个都没过闸 → 直接判这节课不成立**，落"备课本"，
   而且界面**明说是备课本**（不假装是模型给的）。
2. **`school_quiz`**（竞答）：**出三道题 + 定口令**。
   `gateQuiz()` 逐题查：题干够长、选项正好 4 个且互不相同、答案下标没越界。
   另外两件事必须在客户端补，闸拦不住：
   - **答案位置打散**：模型很爱把三个答案都放 A。三道同位置时**就地调换选项顺序**
     （题目、解说、正确内容一个字不动），否则"一路点同一个字母"又满分了。
   - **口令题保底**：模型三道题里没有一道以今晚口令作正确答案 → 客户端补一道，
     否则"口令喂给夜岗"这条线会断（`detail.password` 永远只能是空串）。
3. **`minigame_review` + `operation.type='school' | 'school_quiz'`**：写结局。
   `half` 要写出"传下去会走样成什么字"；口令没教成要写哨位上的后果。

**字段别名容错**：实测模型会用 `type/word/source` 代替 `kind/from`，用 `question/choices/answer`
代替 `q/options/answer_index`。闸**不放宽标准**，但多认几个同义词，能少落几次备课本。

## 九、踩过的坑（这一轮最值钱的部分）

### 1. 坐标系 P0：字被画到判定中心之外 118px（**肉眼完全看不出来**）

`.smini3-row` 挂在**木牌里的 `lit` 层**上，定位父级是木牌；但代码用的是**舞台坐标系**的
`left: bx + pad` —— 于是每个字都被多推了一个木牌偏移（实测 93px）到木牌右外侧。

后果：玩家把光打在**看得见的字**上，判定中心却在 190px 处，**一个字也教不动**。
六种打法全 `0.000`、剩油 0%。

**发现方式**：把行/字/信息盒的 `getBoundingClientRect()` 全打出来对账，
"可见字中心 → 换回设计坐标" 对不上 190.6 就露了。

**修法**：行改用**木牌坐标**（`pad` / `i*cl`），进度条继续用**舞台坐标**（`cy + bot - barH`），
两套坐标系在注释里写明。**回归断言**：光照在看得见的字上 2.6 秒，`miniTaught[0]` 必须 > 0.3。

> 教训：任何"绝对定位 + 多个嵌套定位父级"的地方，都要有一条**"看见的位置 = 判定的位置"**的断言。
> 光靠截图和手感，这类偏移能活很久。

### 2. 文字重叠 -25.5px：条带要**从底往上锚**，行高要**钉死**

"出自「X」"那行是按 `cl*0.60` 写死 `top` 的，窄屏（玩法板内容宽只有 570 → k≈0.79）时
那行类名就爬到"出自"上面去了，重叠 25.5px。

修法：三行信息**从格底往上摞**（`bot = cl*0.95`，条带 `top = cy + bot - barH`），
并把 `line-height` 显式写成 1.4（不然全局 `p` 规则给的是 19.8px，算出来的高度全错）。

### 3. 夜场里的提示文字是**深色**的（等于没写）

`.smini3-hint { color: var(--ink-2) }` —— `--ink-2` 是浅色主题的 `#6a5a42`，
放在**夜色的舞台**上就是黑压压一片。

**规矩**：舞台是夜 → 里面的字色**一律写死浅色**（`#cdc6b4` 这类），不要用 `--ink-*`。
外层（板屏纸面）才用令牌。

### 4. 墨字在亮木头上"糊"

亮木牌 `#cdae7c` 上的 `#2a2015` 太浅。改成 `#150e05` 并补一道极浅的顶影
（`0 1px 0 rgba(255,246,226,.36)`）做出"刻进木头"的凹痕，对比度 7.88:1。

### 5. 导出的观测量比界面**慢一帧**

`miniAnswer / miniPicked` 只在 rAF 里同步，而 `renderQuestion()` 是同步改界面的。
结果：自动化"读 `miniAnswer` → 点对应选项"会读到**上一题**的答案。
修法：`renderQuestion()` 与 `reveal()` 末尾各补一次 `syncData()`。
**契约里写明的观测量，就该和界面同刻一致。**

### 6. 测试自己的竞态（比玩法更容易错）

同一个现象我又踩了一次：逐题循环里**没有每轮重新等 `ask` 并对齐 `miniQ`**，
于是拿上一题的答案点下一题 —— "全答对"跑出 1/3，看着像分档坏了。

**规矩**：驱动"逐题/逐轮"类玩法，每一轮都要
① 等状态 + 等轮次号；② 点完断言 `miniPicked === 期望下标`。两者缺一个，数字就不可信。

### 7. 前台跑长验收会被 SIGTERM

本机 `bash` 通道给的上限约 120 秒，夜校完整验收（6 种打法 + 模型调用 + 3 次固定题）要 4 分钟以上
→ 前台跑会**在跑到一半时被 SIGTERM，日志是空的**，看着像脚本崩了。

**规矩**：这类验收一律 `run_in_background`，并把输出重定向到文件再读。
（另外：回归没跑完时**别另起浏览器实例**，会抢资源把用例挂死。）

### 8. 调试台重复 id

加观测量面板时我一度写出两个 `id="c-outcome"` 和两个 `id="c-mini"`，
`getElementById` 只认第一个 → 读数错位。多面板页每次加面板后都该 `grep -o 'id="[^"]*"' | sort | uniq -c` 点一遍。

### 9. 设计初稿"想当然"，被实测纠正了一处

初稿写的是"灯停在两个字中间 = 一份光劈两半，谁都不够"。
实测（S5）：`0.800 / two / 剩油 0%` —— 两个字**都教成了**。

原因：吞吐是**归一化**的（`prog[i] += dt * raw[i] / Σraw`），
所以"两半"合起来正好等于一次专攻的速度，只是各拿一半速率、且第三个字还是 0。
这不是 bug，是设计的必然结果 —— 但它意味着**"停在交界"是一条合法的保守打法**，
"瞄准精度"只在"三个都要"这件事上才真正要紧（S1 的余量只有 1.1 秒）。

**教训**：机制类判断不能靠读代码推演，要用**固定输入跑出数字**。
这条现在写进了 QA 的 S5 行注释里，免得后人看到"0.800 和 S2 一样"以为是量错了。

### 10. 断言把 dataset 的**字符串**当数字比（假红）

```js
const teachOk = dSnap.focus === 0 && ...       // ✗ 永远是 false
```
`dataset` 读出来一律是字符串：`"0" === 0` 为 `false`。
数字明明全对（偏差 0.6px、完成度 0.90），断言却报 ✗ —— 差点反过来去"修"没坏的东西。

**规矩**：从 DOM / dataset 读来的数值一律先 `Number()`；断言报红时先怀疑断言自己。

### 11. 字压在**照片**上：`getComputedStyle` 量不出对比度，只能采样像素

入口屏的内容是直接铺在板屏底图（`school_close.jpg`）上的，没有纸胎。
于是同一份 CSS，在不同位置的可读性完全不同 —— 底色是**图片**，不是 CSS 背景色。

实测（DPR=2，采 1280 CSS 宽的截图）：

| 元素 | 字色 | 对底实测对比度 | 判定 |
|---|---|---|---|
| `.smini5-lead` | `--ink-0` #241d14 | 8.42:1 | ✓ |
| `.smini5-card .t` | `--ink-0` | 9.94:1 | ✓ |
| `.smini5-card .n`（金签） | `--gold` #a8863f 直压纸面 | **2.04:1** | ✗ 看不出是几个字 |
| `.smini5-foot` | `--ink-2` #6a5a42 压照片暗部 | **2.71:1** | ✗ 连 3:1 都够不上 |
| `.smini5-card .go` | `--ink-2` | **3.97:1** | △ 12px 小字不达标 |
| `.smini5-card .cost` | `--seal` #9b2d24 | **3.79:1** | △ 同上 |

注意 `--ink-2` 就算压在设计纸面 `--paper-0` 上也只有 3.97:1 —— 它是给**微缩装饰字**用的，
负担信息（"考的是…"/"选定之后…"）就会读不清。

**改法（三层，缺一不可）**：
1. 给 `#mini-host` 的内容加一张**纸胎**：`.smini5-wrap { background: var(--paper-veil); border; padding }`
   —— 底从"照片"变回"纸"，对比度就不再随照片明暗漂；
2. 负担信息的字一律抬到 `--ink-1`（#4a3d2c，纸面上 6.28:1）以上，
   "代价"那行用 `--seal-deep`（#6f1f18，5.63:1）并加一道 `border-left`；
3. 金色小签别直接压纸，装进 `--ink-bg-2` 的深色胶囊（金/深底 4.86:1），既达标又保住了金饰。

**验收方式**：`regionContrast(png, box)` —— 在字的外框里取**最暗**像素（字的实心）与
**最亮**像素（没被字盖住的底），比出来就是真实对比度。小字门槛 4.5:1，整屏取最差一处断言。

## 十二、这个仓库的几个坑（与《弯针成钩》那份相同，列在这里免得翻文档）

1. **`runtime-config.json` 覆盖 `.env`**（`server/config.js:40-53`）。接口报错但 `.env` 明明是对的 →
   先看 `runtime-config.json`。
2. **`/api/decide` 成败都返回 HTTP 200**。错误只体现在响应体 `source` 字段与 `logs/ai-calls-<日期>.jsonl`。
   "测试全绿但游戏卡住" → 去 JSONL 里数 `source=ERROR`。
3. **改了 `server/*.js` 必须重启服务**（提示词在 `ai.js` 里，热重载没有）。
   停服务：`netstat -ano | grep :3001` 拿到 PID → 杀 → 重新 `node server/index.js`。
4. 本机**没有 Google Chrome**，浏览器用例要 `executablePath` 指向
   `%LOCALAPPDATA%\ms-playwright\chromium-1223\chrome-win64\chrome.exe`。
5. 别在后台回归没跑完时另起浏览器实例，会抢资源导致用例挂死。
6. `scripts/lint-tokens.mjs` 禁止 CSS 里写死颜色字面量；**JS 里注入的样式不受它管**（本支就走这条）。
