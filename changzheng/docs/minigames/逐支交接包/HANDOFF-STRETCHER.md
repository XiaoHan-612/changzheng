## 一、旧实现薄在哪（重做的理由）

旧版的机制其实**有代价、有失败**（前进/卧倒两键 + 周期炮击），比"点一下播个动画"强。
问题出在**只有一件事，而且画面是示意图**：

| # | 问题 | 后果 |
|---|---|---|
| 1 | **只有"跑 / 趴"一件事** | 没有第二种姿势。史实里担架队的真实两难是**抬与放**：抬着走得快但颠，颠了伤员就淌血。 |
| 2 | **伤员不会更糟、抬担架的人也不会累** | 失血和体力这两个"会变化的量"都不存在 → 没有"什么时候该换肩"的决策。 |
| 3 | 画面是一条地平线 + 三个土包 + 两个箭头小人 | 担架、伤员、弹坑、敌机、渡口灯火——一个都没画。 |
| 4 | 炮击与"敌机扫射"无关 | 史实压力源是**低空敌机的机枪扫射**（见 §四），旧版是抽象周期炮击。 |

## 一·补、本轮修掉的一个"致命 bug"：这支玩法曾经 100% 冻在起点

`draw()` 里弹坑描边写成了 `g.ellipse(x, GROUND + 4, 15, 6, 0, Math.PI * 2)`
—— **少了旋转角，只给了 6 个参数**（`ellipse` 要 7 个）。第一帧就抛：

```
TypeError: Failed to execute 'ellipse' on 'CanvasRenderingContext2D': 7 arguments required, but only 6 present
```

后果：**rAF 回调抛错 → `requestAnimationFrame` 再也不排 → 玩法永久停在开局**
（画面画了一半、看着"有画面"，但 `miniPos` 恒为 0、`miniLeft` 恒为 90、点「放低」也不换姿态）。
对外表现只有一句"**永远不结算**"，从 dataset 上完全看不出是渲染抛错。

为什么上一轮没抓到：`node --check` 语法正确；难度是**帧循环数值模拟**（纯逻辑）调的，
渲染路径不在模拟里；QA 的 A 段只读常量、D 段只取色，都不会抛。

**修法**：补上旋转角 → `g.ellipse(x, GROUND + 4, 15, 6, 0, 0, Math.PI * 2)`。
修完实测：`t=1s 推进 12.1% / 失血 4%`、`t=21s 推进 77.8% / 失血 82%` → **`0.15 / died`（一路抬着走必死）**，
点「放低」carry 1→0 ✓、点「抬着走」0→1 ✓，时间倍率 **0.96×**（没有被拖慢）。

> 配套加固：四支玩法的 QA 都加了**「整轮 0 次未捕获页面异常」**的断言
> （`pageerror` 收集 + 统一挂钩 `browser.newPage` / `context.newPage`）。
> 这一类"渲染路径抛错导致玩法静默冻结"以后会当场红，不必再靠"未结算"去反推。

## 一·补二、本轮修掉的第二个 bug：**换肩冷却从来没上膛 → 体力不是资源**

`SWAP_CD = 5.5` 这个常量导出着、`swapCd` 变量声明着、`b3.disabled = swapCd > 0 || swapLeft > 0`
也绑着 —— **三处都在，唯独没有人给它赋值**。`doSwap()` 只写了 `swapLeft = SWAP_SEC`：

```js
function doSwap() {
  if (phase !== 'run' || swapCd > 0 || swapLeft > 0) return;
  swapLeft = SWAP_SEC;
  swaps += 1;          // ← 少了 swapCd = SWAP_CD
  audio.playSfx('click');
}
```

后果不是"少一个冷却"，是**决策③没了**：硬直一过（1 秒）立刻又能换肩，
等于 **1 秒换 26 点体力**，体力永远满格 → `SPEED_TIRED`（速度腰斩）这个惩罚路径
和"什么时候停下来换肩"这笔账**同时作废**。比 `SWAP_CD` 更老的一版大概是先有冷却后补的硬直，
补的时候漏了一行。

**修法**（三处）：

1. `doSwap()` 里补 `swapCd = SWAP_CD;`；
2. 顺手**直接改按钮的 `disabled` 属性**而不是调 `renderActs()` —— 重建节点会让"正在进行的那一次点击"
   落到已经 detach 的旧节点上（浮桥那支踩过同款坑）；
3. 帧循环里冷却归零的那一帧要重画一次（`disabled` 只在渲染时写），否则按钮**灰了就不再亮**。

**QA 怎么拦住的**：`C5` 原来只断言"点完 150ms 内按钮 disabled" —— 那条**根本拦不住这个 bug**，
因为 1 秒硬直本来就够它变灰。改成了三段式：

| 断言 | 时点 | 拦的是什么 |
|---|---|---|
| `C5a` | 点击后 150ms | 硬直看得见（`disabled=true`） |
| `C5b` | 1.5s（硬直早已结束） | **冷却真的在跑**（仍然 `disabled`）—— 就是这一条能红 |
| `C5c` | 最多再等 9s | 冷却到点**真的放开**（不是永久灰） |

外加 `A6b`：`SWAP_CD > SWAP_SEC`（常量层面声明"换肩之后还有冷却"）。

> 教训：**"按钮变灰了"这种断言要写清楚它排除了哪一种错**。
> 只断言"灰了"，那么"因为别的原因灰的"也会绿。冷却类机制必须一路看到
> **该灰的时段灰、该亮的时点亮**，两头都验。

## 三、这一版是什么

### 三个决策

| # | 决策 | 收益 | 代价 |
|---|---|---|---|
| 1 | **抬着走** vs **放低** | 抬着走快 **3.1 倍**（3.6 vs 1.15 %/s） | 抬着走失血 **2.8 倍**（1.25 vs 0.45 %/s）；**敌机扫射时躲不掉** |
| 2 | **弹坑前放不放低** | 放低过坑稳（0.95） | 抬着过坑 = **2.9 %/s**（坑里颠得最凶） |
| 3 | **什么时候换肩** | 回体力 26、停 1 秒 | 停的那 1 秒不前进（但**失血降到 0.6**，等于"放下的那一下反而稳"）；停完还有 **5.5 秒按不动**（`SWAP_CD`） |

补充：体力见底（`stam ≤ 1`）还硬抬着走 → 速度掉到 2.0、失血 **×1.4**。
→ 所以"不换肩硬撑"是有惩罚的，不是免费。

### 敌机

- 引擎声预警 **1.05 秒**（`PLANE_WARN`）→ 掠过扫射 **0.85 秒**（`PLANE_SWEEP`）。
- 扫射结束那一刻如果**还抬着**（且不在换肩硬直里）→ **中弹**：失血 **+13%**、推进 `−2%`。
- 编队间隔 `PLANE_CYCLE_MIN + rnd * PLANE_CYCLE_RND = 4.2 ~ 6.4` 秒 —— **够密，躲不过来**。

### 失败条件（两条）

| 结局 | 触发 |
|---|---|
| `died` | 失血满 100% —— 担架停下来的时候，天还没亮 |
| `dawn` | 90 秒（`TIME_TOTAL`）走完还没到渡口 —— 渡口封了 |

### 常量表

| 常量 | 值 | 含义 |
|---|---|---|
| `TIME_TOTAL` | 90 | 局内 90 秒（天亮前必须到凤凰嘴渡口） |
| `SPEED_CARRY` / `SPEED_DUCK` / `SPEED_TIRED` | 3.6 / 1.15 / 2.0 | 抬着 / 放低 / 体力见底硬抬 |
| `BLEED_CARRY` / `BLEED_DUCK` | 1.25 / 0.45 | 平地失血 |
| `BLEED_PIT_CARRY` / `BLEED_PIT_DUCK` | 2.9 / 0.95 | 弹坑里失血 |
| `STAM_MAX` / `STAM_DRAIN` / `STAM_RECOVER` / `STAM_SWAP` | 100 / 3.4 / 1.8 / 26 | 体力上下限与换肩回量 |
| `SWAP_SEC` / `SWAP_CD` | 1.0 / 5.5 | 换肩硬直 / 冷却 |
| `PLANE_WARN` / `PLANE_SWEEP` / `SWEEP_HIT` | 1.05 / 0.85 / 13 | 预警 / 扫射 / 中弹扣血 |
| `PLANE_CYCLE_MIN` + `PLANE_CYCLE_RND` | 4.2 + 2.2 | 敌机间隔（够密） |
| `PITS` / `PIT_HALF` | [22,41,63,82] / 4.5 | 弹坑位置（%）与半宽 |

**AI：游戏内 0 次模型调用**（用户原话：担架急送"跟浮桥一个道理"，体验优先）。

## 四、史实锚点

`data/facts.json · h_xiangjiang`（act1）：

> 湘江战役是长征初期最惨烈的战役之一，红军损失极大。

具体到这一支的机制，取自 **1934-11-27 ~ 12-01 湘江，凤凰嘴渡口** 的回忆材料：

- **敌机压得极低、不停扔弹并打机关枪**（蒋济勇回忆）；
  **"最困难的事莫过于在飞机的扫射之下行军"**（莫文骅语）→ `PLANE_WARN/SWEEP/SWEEP_HIT`。
- **夜里行军不能点火**（干部休养连担架队女红军**刘彩香**：摸黑在前方探路，流弹擦过头顶烧焦了鬓角）
  → 画面只有远处火光与曳光，没有灯；**听引擎声卧倒**是唯一手段。
- **一个人照看三四副担架，民夫大多失散负伤** → 体力与换肩（`STAM_*` / `SWAP_*`）。
- **姜齐贤在担架上给杨成武做手术，一路给他洗伤口** → **路越颠，伤员越快消耗**：
  这就是"抬着走快、但失血也快"的直接依据。

**虚构声明**：失血/体力的具体数值、弹坑位置、局内 90 秒都是互动化设计。

## 五、验收

```bash
npm run qa:stretcher    # ~3 分钟
```

| 段 | 断言什么 |
|---|---|
| **A 机制** | 预警 1.05s（听声来得及）· **一次扫射扣 13%**（贪着抬 4 次就满）· 敌机间隔 4.2–6.4s（够密）· **抬着走快 3.1 倍** · **抬着走失血是放低的 2.8 倍** · 换肩停 1s 回 26 · 4 个弹坑都在中后段 · 开局默认抬着走、三个操作元素 |
| **B 三种打法** | **稳**（引擎声就放低 + 体力 < 45 换肩）→ `pass`；**贪**（什么都不做 = 一路抬着走）→ `died`；**只放低 + 短表** → `dawn`；分数分叉 > 0.35 |
| **C 契约** | `host[data-mini]` · 减动效下真点击「放低」命中自己 · 点「放低 / 抬着走」真的切姿态 · 换肩按钮进 1 秒冷却且体力回升 · 结算后操作元素归零 · 状态序列 `run·done` · 整局 **0 次 `/api/decide`** |
| **D 像素** | **右侧远处火光偏暖（r−b 差 > 15）** · 弹坑比地面暗 · 渡口灯火是全画最亮点 · **抬着走时担架真的抬高、放低时真的贴地**（暖木色像素在高/低两条带上的对照） |
| **截图** | `tests/e2e/artifacts/stretcher-run/` |

> ⚠️ **本轮最重要的一次调参（不调就不是游戏）**：
> 初版常数下，"什么都不做、一路抬着走"**稳定通关**（失血 81%，四次模拟种子全过）。
> 也就是说**这个玩法没有失败** —— 恰好就是用户那句判语。
> 处理方式：把 `SWEEP_HIT` 8.5 → **13**、敌机间隔 5.4~8.4s → **4.2~6.4s**，
> 然后用**帧循环数值模拟**在 6 个种子上复核：
> **贪（一路抬着）必死 101–107%；稳（听声放低 + 及时换肩）必过 52%；慢反应 0.35s 也必过 52%。**
> 之后才写 QA 断言。
> → 教训：**手感/难度不要靠肉眼试，先用模拟把"贪必死、稳必过"钉死，再让 QA 去核。**

本轮实跑数字见 `docs/MINIGAMES-GUIDE.md §五`。

## 七、已知欠账

- **弹坑位置是硬编码的固定数组**（`[22,41,63,82]`），每局一样 —— 熟练玩家会背。
  若要随机化，QA 的取色坐标要同步改成从模块常量读。
- **"放低过坑"与"抬着过坑"的性价比几乎相等**（0.95×7.8s ≈ 2.9×2.5s），
  即坑这个决策目前是**中性的**（不吃亏也不占便宜）。想让它更有张力，需要再调一次。
- 失血/体力的积分与敌机时序**未抽纯函数单测**，只由 QA 覆盖。
- **`stitchFrame()` 占位函数已删除**（原来是防未定义变量的临时钩子，抬升逻辑已改为直接判断体力）。
