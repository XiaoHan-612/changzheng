## 零、这一支换掉的是「担架急送」——为什么

用户的原话是「**急送在游戏里已经有两个了，很多了**」，并且让先看这一章在文中的位置再定类型。
查完之后结论是：**这一章缺的本来就不是急送。**

`data/acts.json` 的 act1 是这样的：

| 项 | 值 |
|---|---|
| subtitle | 「代价」 |
| theme | 「队伍为何还在」 |
| 已有玩法 | 热点 `escort`「担架队 · 护送伤员」（`choice`，且是本章 **forced**） |
| 另一个 | 未接线的 `stretcher`「担架急送」（`minigames-story.js` 里的 run/duck） |

也就是说，**这一章已经有两个"抬着人跑"的玩法**，再补一个就是在同一个位置上做第三遍；
而且它的骨（预警窗口 → 按一下 → 扣 1 → 扣满 M 次失败）正是用户已经否掉的那一套。

更要紧的是**这一章的问题不是"怎么跑得快"**。史实上 12 月 1 日主力过江之后，
屏山渡／大坪／界首相继失守，凤凰嘴是最后一个渡口，红 34 师被隔在东岸、几乎打光。
真正要命的事全发生在**天亮之前**：渡口还开着，东岸还有人 —— 你拿什么把队伍接回来。

→ 所以这一支不做"急送"，做**判断**。

## 一、这一支的骨架：回合制的「判断 × 时间账」

**玩家反复做的那件事是「读线索 → 决定这一刻做什么」。**
一共 8 刻，每刻只能做一件事（搜一处／渡一趟）。没有连续量、没有时机窗口、没有空间配平 ——
每一刻都是一次离散的信息判断。

对照另外三支（**四支的骨架两两不同**，这是当初重做的全部理由）：

| 玩法 | 反复做的动作 | 骨架形状 |
|---|---|---|
| 陡坡 v3《拽住他》 | 按住／松开 | **连续**拉锯（张力越拉越危险） |
| 泸定 v2《攀链》 | 贴链 ↔ 直冲 | 两个**互斥姿态**在时间轴上的**排程** |
| 浮桥 | 往哪一段投料 | 不可再生材料在**空间**上的**配平** |
| **收拢（本支）** | **搜一处 / 渡一趟** | **离散回合**里的**信息判断**：线索可信度、旁证排除法、"继续找"与"开始渡"的时间账 |

### 三条代价线，一条都不掷骰子

随机只决定"是哪一个方向"，**不决定"会不会发生"**。结构写死：
2 个「可信」方向（必然有人）+ 4 个「存疑」（其中 2 个有人）+ 2 个「没人提过」（必然无人）
= 8 个方向、东岸 18 人。

1. **刻**：`DAWN = 8`。搜出 4 个有人点最少 5 刻（其中一处有敌情，派人进去要两刻），
   18 人过江要 3 趟 = 3 刻。**5 + 3 = 8，正好用满，一刻余量都没有。**
   → **白搜一处 = 少渡一趟 = 少 6 个人。**
2. **"搜"和"渡"抢同一本账**：8 个方向、8 刻。你**可以把每一刻都花在搜上**，
   然后天亮，一个人也没过去（`crossed === 0`）。**手勤不等于把人带回来。**
3. **有敌情的方向**：派人进去要两刻（人都接得回来）；在外面喊只要一刻，**只回来一半**。
   两刻还是半批人 —— 这笔账要在天黑里算。

### 两条失败线

- **贪搜不渡** → 一个人也过不去（模拟实测 0/18）。
- **不做排除法、顺着名单往下扫** → 稳定掉到 12/18（模拟实测 12~12）。

## 二、史实锚点

## 五、难度：先跑模拟钉死，再写断言

`npm run sim:rally` —— 8 套打法 × 4 个种子，读 `dataset` 上暴露出来的面决定点哪里，

### 本轮实测（`decide=0`，全程 0 次模型调用）

| 打法 | 过江 min~max | 说明 |
|---|---|---|
| `oracle`（偷看真值） | **18 ~ 18** | 满分可达 |
| `clue`（做排除法） | 12 ~ 18 | 好打法能满分，**但不是每局都能** |
| `blind`（不看线索、顺着编号扫） | **12 ~ 12** | "手勤"稳定掉档 |
| `slip2`（开局误判两次） | 6 ~ 15 | 一次误判就是 6 个人的代价 |
| `callout`（在外面喊） | 15 ~ 18 | 省一刻、丢一半 |
| `noWarn`（死活不碰有敌情的方向） | 12 ~ 15 | 不敢冒险同样要付钱 |
| `greedy`（只搜不渡） | **0 ~ 0** | 手勤到极致 = 一个人也过不去 |
| `ferryOnly`（只渡不搜） | **0 ~ 0** | 江边没人时，渡一趟就是白等一刻 |

### ⚠️ 这份模拟两次推翻了设计 —— 都是先跑数、再改常数

1. **初版有"小组"配额**（每搜一处耗一个）：配额把"贪搜"的玩家**卡住**搜不动、
   反而**被迫**去渡 —— 越浪费越安全。
   → **失败的边必须由时间画，不能由配额画。** 小组整个删掉，只留"刻"一本账。
2. **改完只剩"刻"、但取了 9 刻**：模拟一看，`clue` 四局全 18/18 满分 ——
   多出来的那 1 刻等于**白送一次误判**，失败边被抹平。
   → 收到 **8 刻**，与最优线**等长、零余量**。
   **预算必须与最优线等长；只要多一刻，判断就变成可以偷懒的事。**

## 九、这一轮踩到并修掉的坑（做下一支会再遇到）

### 1. 模拟/QA 脚本只挂两道硬退是不够的 —— 会静默死掉

顶层 `await` 抛出的错，在 Node 默认的 `--unhandled-rejections=throw` 下**不走**
`unhandledRejection`，而走 `uncaughtException`。本轮一个策略里的 `ReferenceError`
让整轮模拟**只留下两行表头就消失**（进程没了、日志没报错），排查花掉了一整轮。
→ **看门狗 + `unhandledRejection` + `uncaughtException` 三道都要挂**，并把 `stack` 打出来。

### 2. 断言策略本身也会写出 bug，而且长得像"这个玩法太简单"

`POL.oracle` 里写了 `v.truth.map((n, i) => i).filter((i) => n > 0 …)` —— `n` 出了作用域。
它和 `.map((k,i)=>i).filter((i)=>…know[i]…)` 只差一点，肉眼看不出。
更隐蔽的是 `smart()` 拿了 `unsearched()`（只排除"已搜"）而不是"已知为空也排除"，
于是策略会**对旁证已经判过"是空的"方向下注** —— 量出来的难度是假的。
→ 写策略时问自己：**这个策略里，哪些信息是"玩家真的知道"的？**

### 3. 数像素前，先确认"你数的那块真是你以为的那块"

画作四边有撕纸边（米黄/棕褐），它同样满足"暖 + 亮"，把 F2 骗过去了（详见 §六）。
→ 量坐标前先用 PIL 出**亮度图 + 暖色图**，把画作坐标"看"出来；
   **别用印象放覆盖层，也别用印象写断言。**

### 4. `boundingBox()` 是 async，漏 `await` 会把 Promise 当 clip 传进去

报错是 `page.screenshot: clip.x: expected float, got undefined`，
断在截图这一步、后面整段验收全丢。顺手也把"取不到元素框"显式抛出来。

### 5. 策略在"只剩空渡"时会僵住，而玩法里没有"干等"这个动作

`noWarn`（死活不碰有敌情的方向）把能搜的都搜完、江边还没人时，只剩"空渡到天亮"这一个合法动作。
策略返回 `null` → 驱动退出 → 整局永不结算 → 四局全 `ERR no-resolve`。
→ 驱动策略的两道兜底：**① 还有没搜的就去搜；② 能搜的都搜完了也得渡。**
（玩法本身没问题：`ferry` 永远可点，所以**永远存在合法动作**、不会死局。）
