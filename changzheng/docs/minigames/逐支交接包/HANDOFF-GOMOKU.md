## 一、旧实现薄在哪（重做的理由）

旧版是 **9×9 的 81 个 `<button class="wzq-cell">` 排成方格**，点一下变个色块；
对手是"优先成五、其次封堵、再者为邻近空位"的一步贪心。三处硬伤：

| # | 问题 | 后果 |
|---|---|---|
| 1 | **没有棋盘，只有方格** | 画面上是 81 个色块矩阵 —— 没有划痕、没有泥、没有石子体积，也没有"这是在草地上"的任何痕迹。 |
| 2 | **没有代价，也没有第二次决策** | 除了"往哪儿落子"玩家不做别的选择；输了就是 0.25 分，没有"我在赌什么"的感觉。 |
| 3 | **对手是死的** | 同一套贪心，每局一样，玩家两局就背下来了。 |
| 4 | 顺带修掉的静默 bug | 旧版给棋子加的是 `p1/p2` 类，而 CSS 里只有 `.black/.white` → **棋子一直是空圈**。类名对不上就是这么静默地坏掉。 |

## 三、这一版是什么

### 四重决策

| # | 时机 | 决策 | 真的改分数吗 |
|---|---|---|---|
| ⓪ | 开局 | **对面坐谁**：三档（心不在焉 / 认真起来 / 把老兵教的使出来）。差别不是"噪声大小"，是**他看得见多远的杀招**：只看四 / 也看四 / 还能算双活三 | 间接（决定难度） |
| ① | 开局 | **接不接让子**（小鬼先开口）：接 → 你先连落两子但**结算上限压到 `CAP_HANDICAP = 0.72`**；不接 → 上限 `1.00`，但输面实打实 | **是**：直接改上限 |
| ② | 中盘 | **水洼往哪儿渗**：从第 8 手起每 4 手渗一处（最多 3 处），**渗水前一回合先显湿痕**。水洼格不能落子 → 渗水是**资源**：能封对手的线，也能堵自己的路 | 是 |
| ③ | 随时 | **蹲一边看他俩下**（观棋）：两个 AI 各问一次（并发），你只做判断 | 是（观棋独立结算线） |

### 画面（按史实重做）

- **泥地划痕棋盘**：线是歪的（树枝刮的），有泥的颗粒与湿痕；
- **石子有体积**：深的是**湿青灰石**、浅的是**干石灰石**，挑自泥里；
- **是夜里、围着篝火**下棋（篝火光落在棋盘留白那一圈上）—— 手是冻的。

### 常量表

| 常量 | 值 | 含义 |
|---|---|---|
| `N` / `CELL` / `PAD` / `BOARD_PX` | 9 / 34 / 12 / 330 | 9×9 —— 泥地上用树枝刮得出来的尺寸 |
| `PUDDLE_MAX` / `PUDDLE_FIRST` / `PUDDLE_EVERY` | 3 / 8 / 4 | 水洼上限 / 从第 8 手起 / 每 4 手一处 |
| `AI_WINDOW_MS` | 10000 | **用户定的窗口**：超过 10 秒当作"它没答"，走本地兜底 |
| `CAP_HANDICAP` / `CAP_FAIR` | 0.72 / 1.0 | 接让子 / 实打实的结算上限 |
| `SPECTATE_SCORE` | 0.5 | 观棋线的基准分 |
| `LEVELS` / `RANK_BONUS` / `DEFAULT_LEVEL` | — / — / `'mid'` | 三档对手 |

### 纯函数层（**这一支的独特之处**）

`mulberry32 · makeBoard · toBlocked · legalMoves · pointScore · noteOf ·
chooseMove · topCandidates · findFive · longestRun · planBand · gradeGame ·
gradeSpectate · boardText · cellCenter`

→ 判定逻辑全都抽成了**可单测的纯函数**（其余四支还没做到）。
**但 `tests/unit/minigames-*.test.js` 还没建** —— 见 §七。

### AI 的两条用途（默认 0 次调用）

1. **让小鬼子自己想办法**：引擎先给 4 个候选（`topCandidates`），模型只挑一个 + 配一句话；
   **10 秒窗口，随时可「催他一手」**。
2. **蹲一边看他俩下**：两方各问一次，并发。

## 四、史实锚点

`data/facts.json · h_grassland`（act4）：1935 年 8 月，红一、红四方面军走过松潘草地；
气候恶劣、沼泽遍布、补给断绝。公开史料（人民网 / 中国军网 / 央视"过草地"专题）里
三条被反复写到的细节，直接变成了画面与规则：

| 史料 | 变成什么 |
|---|---|
| "8 月是草地最暖的季节，白天最高可达 30 度，**一到夜间就降到 0 度左右**" | 所以是**夜里**、围着**篝火**下棋 |
| "河沟交错，**积水呈淤黑色**，草丛下是沼泽泥潭" | **泥地棋盘 + 渗水**：水洼里落不住石子（核心机制） |
| "**没有树、没有石头**做参照，只有沼泽上一丛丛几尺高的乱草" | 棋子是**从泥里挑出来的石子**（湿青灰 / 干灰白），棋盘是**树枝刮的** |

**虚构声明**：三档对手的搜索深度、让子上限 0.72、水洼节奏都是互动化设计。

## 五、验收

```bash
npm run qa:gomoku      # 带 --no-model 全程 0 次真调用
```

**本轮实跑：40 项全绿。** B 段四打法分叉：**1.00 / 0.12 / 0.72 / 0.20**
（实打实赢 / 输 / 接让子赢被压到 0.72 上限 / 观棋输）。

| 段 | 断言什么 |
|---|---|
| **A 机制** | 棋盘几何 9×9 / `BOARD_PX = 330` · 水洼节奏（第 8 手起、每 4 手、上限 3）· 让子上限 `CAP_HANDICAP = 0.72` 真的压分 · 10 秒窗口 `AI_WINDOW_MS` |
| **B 四种打法** | 实打实赢 → 1.00；输 → 0.12；接让子赢 → **被压到 0.72**；观棋 → 独立结算 |
| **C 契约** | id / 状态序列 `setup·play·think·spectate·spectate-think·done` / `[data-mini-action]` 齐全 / **减动效下真点击落子** / 结算后操作元素归零 / 0 次 `/api/decide`（`--no-model`） |
| **D 像素** | 泥地**划痕线是歪的**（不是网格）· 两种石子**色温可区分**（湿青灰 vs 干灰白）· 篝火光落在棋盘留白圈上 · 渗水湿痕与"落不住"的水洼在像素上可辨 |
| **截图** | `tests/e2e/artifacts/` |

### 本轮顺手修的三处（都是**全屏看截图**才发现的）

| 问题 | 修法 |
|---|---|
| setup / 结算屏上留着一个 **40px 高的空纸框**（台词元素在但没内容） | `renderSay` 里加 `sayEl.hidden = !text`；初始 mount 调 `renderSay('', '')` |
| **结算后没有收尾台词**（台词被清空，画面突然安静） | `finish()` 改成给一句小鬼的收尾（赢/输/平三句不同） |
| **setup 屏重复显示对手行**（面板与台词都在说同一件事） | `renderKv()` 在 `setup` 不再重复对手行，且空则隐藏 `kvEl` |

> 教训（已写进 `docs/MINIGAMES.md`）：**只看 canvas 截图不够，必须看整屏截图** ——
> 空纸框、重复行、缺席的收尾台词，全都在 canvas 之外。

## 七、已知欠账

- **纯函数层已导出但没有单测**：`tests/unit/minigames-gomoku.test.js` 还没建。
  这是全项目最该补的一支（`chooseMove` 的"威胁阶梯"曾经有过 bug，靠 QA 才抓到）。
