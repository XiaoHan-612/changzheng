## 三、这一版是什么

老班长的炭盆边，就一根缝衣针。三种死法、四个决策、成品是一枚真钩。

### 三个决策（每一个都要付代价）

| # | 决策 | 代价 / 死法 |
| --- | --- | --- |
| 1 | **烧到多少度** | 低于 50 针身发青、**一弯就断**；高于 92 钢开始"酥"，酥到 100 针就废了 |
| 2 | **什么时候弯** | 针离火就凉、弯折本身也在散热。**要弯，就得让它待在 50–90 这条带里** |
| 3 | **弯到多少停手** | 钩门（222–250°）与钩尖（42–64°）各有甜区；不够＝挂不住鱼，过了＝崩口断针 |

### 三种死法（都会让你手里只剩半截针）

| 结局 | 触发 | 画面 |
| --- | --- | --- |
| `snapped` | 温度 < 50 时继续用力弯，撑 0.5s | 弯折点先闪一道亮缝，然后"咯"一声断成两截，落到毡子上 |
| `snapped` / `tipbreak` | 钩门 > 292° / 钩尖 > 92° | 崩口，针尖崩掉一截 |
| `burnt` | "酥"积到 100（过烧 92° 以上快速累积；每次回火也加 3.5） | 针身起白、掉渣，然后断 |

### 与《金色的鱼钩》的关系（用户点名要的）

理想钩 = 钩门 236° + 钩尖 53° = **289°**，
而钓鱼那支钩画的是 `arc(cx, cy-r, r, π*0.12, π*1.72)` = 1.6π = **288°** —— 同量。

成品用的就是**同一支金色 `#e3bd66`、同一档辉光**；定妆镜头把它冷却、擦亮、立起来，
跟钓鱼特写里那枚钩一模一样。**弯出来的就是那枚钩。**

### 怎么玩

画布下面四个钮，也可以直接用键盘（更快、更准）：

| 钮 | 键 | 干什么 |
| --- | --- | --- |
| 按住烧针 | `1` | 把针伸进炭火，温度上升（74°/s），同时针身的"酥"开始积 |
| 按住弯钩门 | `2` | 弯大弧（58°/s） |
| 按住弯钩尖 | `3` | 弯尖（78°/s） |
| 就这个了 | `回车` | 交针，进定妆镜头，出分 |

**上手一句话**：烧到樱红（50–90）就别再烧了 → 趁热弯一段 → 凉了再烧一次 → 再弯 →
钩门到 236、钩尖到 53 就交。**右上角那枚虚线钩是样板，你的针会叠在它上面。**

## 六、机制数值（都是调过的，别随手改）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 升温 / 降温 | +74 / −12 （弯折时再 −5） | 甜区 40 度宽，一次火够弯 2 秒多 |
| 火候甜区 | **50 – 90** | 与钓鱼的张力甜区 45–82 同一个意思：一个不能太松、一个不能太凉 |
| 过烧起点 | 92 | 往上按超出量加权积"酥"，最快 26/s |
| 回火代价 | 每次重新伸进火里 +3.5 酥 | 反复加热让钢变脆——这条堵住了"小口多次烧"的无限续命 |
| 冷弯断裂 | < 50 还弯，撑 **0.5s** | 到 0.18s 会先"咯"一声预警 |
| 钩门弯速 / 上限 | 58°/s ／ 292° 断 | 甜区 222–250 |
| 钩尖弯速 / 上限 | 78°/s ／ 92° 断 | 甜区 42–64 |
| 计分 | 钩门 0.44 + 钩尖 0.32 + 针身 0.24 | `0.24×(1−酥/100)`，所以"好钢"本身也是分 |

**为什么两次火是下限**：100° 满温一次火只能弯 2.9 秒（约 168°），够不到 236°。
所以正常一局至少两次火、两次弯 —— 那个"再烧一回、钢就脆一分"的取舍是被迫发生的。

## 八、画面（这一版的重点）

- 夜雨里的草地：铅灰夜空、斜雨、两道草丘脊线、雾里三顶帐篷剪影（最左边那顶后头一点营火余烬）
- 地上一只**铁皮盆**：盆口的搪瓷高光、一圈黑炭、中间几块烧红的（带辉光）
- **火**：七条火舌各自抖（bezier + 叠加混合）、火心、上升的火星；雨点落上去会"嘶"
- **针**：三段不同粗细（3.0 / 2.6 / 1.7）+ 一条上缘高光 + 针眼那道长槽；
  颜色随温度走 **冷灰 → 暗红 → 樱红 → 橙黄 → 白热**，赤热时整根往外散光
- **钳子两把**：左手夹住针眼端、右手夹在弯折点前——**弯折只发生在钳口以外**，跟真活一样
- **针在火里**：整根针下移到火苗中，火苗再补一层盖住下半，火也随呼吸变高
- **冷着硬弯**：弯折点上先闪出一道裂缝，"咯"一声才断
- **断针**：两截各自带一点旋转落到毡子上，撞出火星 + 画面轻微抖动
- **定妆**（交针后 1.6s）：冷却 → 一道光从针眼端扫到钩尖把它**擦亮成金** → 立起来 → 停在画面中
- **右上角样板框**：虚线画的是理想钩（同一套路径积分算的），你手上的针叠在上面实时对比；
  坐标系按「整根直针 ∪ 理想钩」定死，弯折过程中画面不跳
- **仪表盘**：火候（甜区高亮 + 刻度）/ 钩门 / 钩尖三条，底下一条细的"针身（酥）"

### 画面上的字为什么是糊的（2026-09-15 用户反馈后修）

用户看完第一版说"画面还行，就是里面的文字有点糊"。**不是分辨率不够，是字太小 + 用了宋体**。

根因（三条叠加）：

1. **"设计像素"失去了物理意义。** 画布写死 `canvas.width = 720 × DPR`，而元素被 CSS 压到
   **570 宽**显示（`--panel-w: 620px` 减去左右 `--sp-5: 24px`）→ 缩放 **0.79**。
   于是 HUD 里写死的 `10px` 落到屏幕上只有 **7.9px**。
2. **这 7.9px 还是宋体。** 字的 font stack 用的是 `--font-num`，而它是
   `num, serif, Georgia, serif` —— 数字吃 EB Garamond（拉丁字体），**汉字落到第二顺位的
   serif（Noto Serif SC）**。宋体的横细竖粗在 8px 上下笔画直接断掉。
3. **纸面上的提示文字是 11px + `--ink-2`**（纸色上最浅的一档褐），对比度也不够。

修法（正面修，不是把字号调大碰运气）：

- **后备缓冲跟着实际显示宽度走**：`canvas.width = 显示宽 × DPR`，
  `1 设计单位 = viewScale 个 CSS px`（`viewScale = 显示宽 / 720`）。
  顺带把 1440 的后备缓冲缩到 570 显示这个浪费也去掉了。
- **HUD 字号按物理像素定死**：设计字高 `fpx = HUD_PX / viewScale`，反向放大。
  画布多窄，字在屏幕上都是 **13 CSS px**。上下限 `HUD_FP_MIN/MAX` 防止极窄画布把排版撑破。
- **小字的 font stack 换成无衬线**：数字仍吃 `num`（保住项目味道），
  汉字落到 `"Microsoft YaHei" / "PingFang SC" / "Noto Sans SC"`。
- 纸面提示 11px→13px、`--ink-2`→`--ink-1`；状态行 13px→15px。
- 顺手把仪表盘改成**三列等宽 166 / 间隔 17**（16、199、382，右止 548，避开 578 起的样板框）——
  字变大之后原来的 226/168/124 会让标签互相撞。

**证据（实测，不是算术）**：`qa-needle.mjs` 里加了一段字号体检，用 `ctx.measureText('火')`
真量一个汉字 —— 修复前 `10 × 0.79 = 7.9` 屏幕 px，修复后 **12.99 屏幕 px**；
`ctx.font` 回读确认栈里已是 `Microsoft YaHei`（无衬线）。

> **给后面所有 canvas 玩法的教训**：只要画布用 `width:100%` 而设计宽度是固定的，
> "设计 px"就**不等于**屏幕 px。所有画在 canvas 上的字都必须按
> `目标屏幕字号 ÷ viewScale` 反算，否则换个布局宽度就会重演一次"文字发糊"。

### 金色像素断言怎么做的（因为截图人眼看不了）

模型读图会被过滤，所以"钩是金色的"这句话必须**能被脚本证实**。做法是扫描 canvas，
筛出"像金"的像素，回报**数量 + 包围盒**（换算回 720×400 逻辑坐标）。

**关键教训：金和火只能靠位置分开，不能靠颜色分开。** 金色 `#e3bd66 = (227,189,102)`
本来就是炉火色，而火苗的 `mid→core` 渐变 `(255, 154+76t, 60+116t)` 在某个 t 上会落进
同一个色比窗口。实测"满画面扫"—— **在什么都没做的时候也能数出 1220 个"金"，
包围盒 `179,280 → 319,324`，那全是炭盆的火苗。**

所以判据是两条一起用：

| | 内容 | 作用 |
| --- | --- | --- |
| ① 色比窗口 | `g/r ∈ [0.78,0.90]` ∧ `b/g ∈ [0.47,0.60]` ∧ `r+g+b > 380` | 保证"像金" |
| ② 取样框 | `x 296–352 / y 176–258` | 保证"在钩应该在的地方" |

取样框是**定妆位钩身上半段**：钩门 236°+钩尖 53° 立起来之后，钩身占 x 308–341、y 181–287；
而火苗最高只到 y≈266（`baseY 324 − 最大火舌高 58`），框底 258 在它之上 —— 所以框里不可能有火。

对照组（同一时刻）：
- reset 之后的**冷直针**（灰 `201,206,210`，`g/r = 1.02`）→ 框内 0 个
- **烧废之后**（针断成两截、躺在工作位）→ 框内 0 个

**⚠️ 第三条弯路：原始像素个数会随后备缓冲分辨率变。** 画布改成"后备缓冲 = 显示宽 × DPR"
之后，同一枚钩在 DPR 2 下是 **421 px**、在 DPR 1 下只剩 100 出头 ——
阈值若写死 200，换个屏就会把一个**正确**的画面判成红的。
所以判据用 **`n / dpr²`**（归一化回"设计单位面积"）：旧布局 `693/4 = 173`、
新布局 `421/2.49 = 169`，两次几乎一样，与设备无关。阈值取 **`> 60` / `< 12`**。

这套断言不是走形式：它**真的抓出了两个缺陷**（见 §九），其中一个把整根钩画到了画布外面。
**而且它自己的检出能力也是验过的** —— 缺陷在的时候框内读数是 **0**，修好之后是 **169（归一）**，
不是"加了断言之后永远绿"。

### 顺带一提：`S2 烧废` 那一行是有效的对照组

S2 跑完之后，框内是 0 个金 —— 因为针断成两截躺在工作位，根本没到定妆位。
所以"**169 vs 0 vs 0**"这三个数放在一起，证明的不是"画面里有金色"，而是
**"金色只在那枚弯成了的钩上"**。

**修掉的四个缺陷（都是自己写出来的，前三个靠脚本才逼出来）**
1. **断针后按残段重绘会抛错**：`drawNeedle` 始终按整根 25 个采样点取 `pts[18]`，
   而残段只有 7 / 13 个点 → `Cannot read properties of undefined (reading 'x')`
   → **rAF 循环当场死掉** → 三条失败路径全部卡在"没拿到 resolve 结果"。
   改法：三个分段点夹到实际长度（`Math.min(IDX_A, n)` 等）。
   检出方式：**这是脚本跑出来的**——第一次跑，S2/S3/S4 三格全是"没拿到 resolve 结果"，页面报错栏里三条同类错误。
2. **"金色"在 resolve 之后会消失**：render 里写的是 `else if (phase === 'showcase')`，
   而定妆跑完 `phase` 变成 `'done'` → 钩子当场弹回工作位、金色褪成铁色。
   改法：改用**持久状态**判断（`broken` / `showcase > 0`），不看瞬时的 phase。
3. **定妆把整根钩画到了画面外**：`SHOWCASE` 是屏幕坐标，但那一层已经被
   `translate(TAIL_X, needleY)` 平移过，屏幕坐标直接喂进去会被再加 (132,200)
   → 钩中心落到屏幕 y≈434，**而画布只有 400 高**。
   改法：`g.translate(tx - TAIL_X, ty - needleY)`，先换算回本层局部坐标。
4. **画面上的字只有 7.9px 且是宋体**（**用户看出来的**，前三个人眼和脚本都没发现）。
   前三个缺陷是"画面全错"或"流程卡死"，这一个只是"不好看"，
   而所有功能断言都是绿的 —— 说明**功能全过 + 页面不报错 ≠ 画面能读**。
   见 §八「画面上的字为什么是糊的」。

## 十二、这个仓库的几个坑

- **同一文件不要并行发多个 Edit**：会互相覆盖，只有最后一个生效（真踩过，表现为"文件一半新一半旧"）。
- **`npm` 在这个 bash shim 里跑不了**（`/usr/bin/env: bash: No such file or directory`）：
  直接调脚本，如 `node --test tests/unit/*.test.js`、`node scripts/lint-tokens.mjs`。
  shim 还缺 `ls/tail/head/dirname`，用 `node -e` 代替。
- **前台跑截图脚本会被 SIGTERM**（长任务），**用后台跑**：
  `node tests/manual/qa-needle.mjs > tests/e2e/artifacts/needle-log.txt 2>&1 &` 然后读文件。
  结尾 `browser.close()` 偶发挂住 —— 产物与日志其实已完整，别据此判定失败。
- **浏览器缓存**：静态资源 `max-age=3600`，调试台已加时间戳；主线页面要 Ctrl+Shift+R。
- **本机没有 Google Chrome**：Playwright 用例硬编码 `channel:'chrome'`，要跑得手动指定
  `%LOCALAPPDATA%\ms-playwright\chromium-1223\chrome-win64\chrome.exe`。本支的脚本已经自动找。
- **CSS 层序**：屏内 `*-bg` 是 `position:absolute`，会盖住 static 内容盒；
  带背景层的新屏必须给内容盒 `position/z-index`，否则 `prefers-reduced-motion: reduce` 下全点不动。
- **板屏测试别用 `click({force:true})`**：会把"元素被遮挡"整类缺陷屏蔽掉。
- **`token lint` 只扫 `public/css/*.css`**，不扫 JS 里注入的样式；但仍建议只用 `var(--*)`。
- **配置层**：`runtime-config.json` 覆盖 `.env`（见 `server/config.js:40-53`）。
