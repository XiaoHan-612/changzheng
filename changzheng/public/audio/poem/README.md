# 终局升华的朗诵音频（整段录音）

**这个目录里的音频随仓库一起走**（2026-09-16 起）。当前放的是：

| 项 | 值 |
|---|---|
| 文件 | `qilv-changzheng.mp3` |
| 它是什么 | 一段《七律·长征(朗诵版)》的朗诵录音（文件自带的 ID3 标签就写着这个标题与"诗歌朗诵"） |
| 规格 | MP3 / 44.1kHz / 立体声 / **59.3 秒** / 949,376 字节 |
| 谁在用 | 终局升华那屏的 `poem` 拍子（`modules/cinema`）：题字跟念白淡入 → 八句逐字 → 钤印 |
| 逐句时间轴 | 写在 [`data/poem.json`](../../../data/poem.json) 的 `lines[].startMs/endMs`，**是量出来的**（见下） |

## 它怎么被接上（两条路，任选）

1. **整段录音（现在走的就是这条）**：文件名填在 `data/poem.json` 的 `audio.full`，
   每句的 `startMs/endMs` 给时间轴。逐字按"锚点 + 挂钟"推，**文字比音频早 500ms**
   （口径：不追精确对齐，宁可字先出、别让人等）。
2. **逐句配音**（备用，可用）：按 `npm run poem:manifest` 生成的 [`docs/POEM-TTS.md`](../../../docs/POEM-TTS.md)
   把 8 个单句 wav 放进 `public/audio/cache/`（与其它 TTS 台词同一条产线，`/api/tts` 自动命中）。

两条路都没走通也能演——屏幕按 `data/poem.json` 的 `pace` 逐字走，流程不阻塞、不报错。

## 时间轴是怎么量的（要换音频就照做一遍）

没有 ffmpeg 也能量：在浏览器里 `decodeAudioData` 拿 PCM → 20ms 窗算 RMS 包络 → 按静音分段。
本段实测：59.25s 里有声段 16 个，用 800ms 合并窗口得 10 段 = **报题 2 段**（「七律·长征」「毛泽东」，
2.3–7.4s）+ **八句**（每句 3.5–4.8s，句前都有 ≥1.2s 停顿）→ 于是第 1 句 11.4–15.2s …
第 8 句 51.5–56.3s。完整口径见 [`docs/HANDOFF-AUDIO.md`](../../../docs/HANDOFF-AUDIO.md) 第六点五节。

## 换一版音频怎么办

1. 把新文件放进本目录（文件名随意，建议沿用 `qilv-changzheng.ogg` 这类清晰命名）；
2. 改 `data/poem.json` 的 `audio.full` 指到它；
3. **重新量一遍逐句时间轴**（上一节的办法），把数字写回 `lines[].startMs/endMs`；
4. 跑 `npm run qa:audio`——它会核对"目录里的文件有没有被 `audio.full` 指到"，漏填会红。

**格式**：`.ogg` / `.wav` / `.mp3` 都行（`qa:audio` 会逐个解码核对容器与时长；mp3 这一种是 2026-09-15
为这段录音放开的，"只认 WAV/Ogg"那条本来是为了防扩展名与内容不一致）。
