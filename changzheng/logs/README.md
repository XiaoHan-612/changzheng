# logs/ 目录说明

| 文件 | 入库 | 用途 |
|---|---|---|
| `sample-full-run.jsonl` | ✅ 入库 | **样本**：2026-09-13 连续跑的三段真调原样截取（沙盘/回归 → 五幕研学通关 → 行军模式失败线），96 条、覆盖**当时全部 16 类** callType、全部带 `contractOk` 戳记（其中 `sim_turn` 属已删的「自由行军沙盘」，**本版本的调用面是 15 类**，样本保留原样）。用于离线查看记录格式、跑 `npm run qa:audit`、以及答辩时说明"每次 AI 决策都有日志" |
| `ai-calls-<日期>.jsonl` | ❌ 不入库 | 运行产物：每局游戏（和每次测试）实时追加，单文件 8MB 轮转。演示后想看这一局的 `aiCount` / `source` 就看这里 |
| `session-full.jsonl` | ❌ 不入库 | 同一批记录的会话镜像，供游戏内「行军记录」与答辩面板读取（`/api/logs`） |
| `shots/` | ❌ 不入库 | `tests/manual/shot-all.mjs` 出的逐屏截图（视觉体检用），可随时重跑 |
| `archive/` | ❌ 不入库 | 本机留存的旧日志（不入库，也不参与审计）。仓库里曾经跟踪过 `ai-calls-*.jsonl`，2026-09-13 起改为只留样本：日志是运行产物，逐日变动会把 diff 冲成噪音（旋转还会把当天最早的记录裁掉，见 `docs/QA.md`） |

**为什么只留一份样本**：日志是运行时产物，不是源码；但"每次决策可审计"是这个项目的卖点，
所以仓库里留一份**未经修改的真实全程日志**，剩下的交给运行时（`server/logger.js` 落在 `logs/ai-calls-<日期>.jsonl`）。

**审计怎么算**：`npm run qa:audit` 读本目录下所有 `*.jsonl`（不递归，所以 `archive/` 不会进来）。
入库样本全部带 `contractOk: true` 戳记，因此在新克隆的仓库里跑审计应当是
「本版本 96 条 · 缺失 0 · 历史 0」；本机若又跑过测试，会多出带戳记的新记录，同样是 0 缺失。
